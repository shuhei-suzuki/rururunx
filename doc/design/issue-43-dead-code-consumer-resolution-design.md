## 3. Preparation known-commit reconciliation caller (D11)

**Problem.** If `begin_native_preparation` (`preparation.rs:1076`) returns `Err`, the commit outcome is uncertain. The start returns `Err`, `phase_jobs.rs:782` calls `preparation.abandon()`, and the custody is `abandoned`, actor revoked, `plan` Some, `known` None, no helpers, no `no_dispatch`, no transport. RN's `nonsuccess_step` reaches "pre-no-dispatch start ended; Held" and the sweep re-holds it every 5 s (`phase_jobs.rs:445–447`). The preparation HOW §3.2 (l.282–290) requires known-commit reconciliation: "Only that original known commit or exact original sealed postimage confirmation can record `NativePreparationCommit`; exact rollback/absence permits only an original eligible retry … At most one exact reconciliation attempt is made per due wake with capped backoff." `reconcile_known_commit` implements the attempt but has no caller (RN1 l.71).

**Constraints.**
- `reconcile_known_commit` is async: its plan branch awaits `PhaseEffectAdmission::enter` (`runtime/phase_effect_admission.rs:55`), which awaits `control_admission.lock_owned()`.
- Shutdown holds `control_admission` while it awaits the service loop handle for 5 s (`runtime/service.rs:126–141`). An awaiting acquisition inside the loop would stall shutdown until "control loop shutdown remains pending". The loop's existing idiom is `try_lock` (`runtime/admission.rs:37`).
- RN's sweep is synchronous and must not await.

**Design (P).**
1. Add `PhaseEffectAdmission::try_enter(launch) -> Result<Option<PhaseEffectAdmissionGuard>>`: the same checks as `enter` (acceptance, owner/admission identity, retained membership), with `control_admission.clone().try_lock_owned()`; `None` when busy. `enter` is unchanged.
2. Add a Root-only entry `NativePreparationCustody::confirm_preparation_nonblocking(self: &Arc<Self>) -> Result<PreparationConfirm>` that covers **only the plan branch** of `reconcile_known_commit` (R2, DC-M01): it re-checks the custody predicate of step 3, takes `try_enter`, runs `confirm_native_preparation` once, and retains a Known commit. It never enters the transport, closure or helper branches. **R3 (R2-M01):** `reconcile_known_commit` is deleted and this entry replaces it (it had no caller in production or tests at `732a88c`; the callees of its non-plan branches keep their own production callers, see D11). The plan-branch body (actor/sessions upgrade, admission, one `confirm_native_preparation`, `retain_commit`) moves into this entry with `enter` replaced by `try_enter`. `PreparationConfirm` is `{ Known, NotAttempted, Held }`: `NotAttempted` when the admission is busy (DC-L01), `Held` for every confirmation `Err`.
3. Add `PhaseJobs::reconcile_preparations(&self, stopping: &AtomicBool) -> Result<PreparationSweep>`, called synchronously from the service loop right after `reconcile_nonsuccess` (`runtime/service.rs:91`). It snapshots ≤128 entries (same `closure_snapshot`), selects jobs whose start ended (`ended` predicate, `phase_jobs.rs:398–402`) and whose custody reports the uncertain-preparation predicate (`plan.is_some() && known.is_none() && no_dispatch.is_none() && transport.is_none()` via a new nongrant `NativePreparationCustody::known_commit_due()`), whose own `preparation_due` has passed. It returns at most 8 custody `Arc`s (rotating `preparation_cursor`), never holding a Root lock afterwards.
4. The service loop then, after dropping its strong `Runtime` (pattern at `service.rs:104`) and holding only the returned custody `Arc`s, awaits for each: `custody.confirm_preparation_nonblocking()` (R3, R2-L01: the single entry name of step 2). Each attempt is one admission try plus at most one Store transaction (`confirm_native_preparation`), so "at most one exact reconciliation attempt per due wake" holds.
5. **Outcome handling (R2, DC-M02, DC-L01, DC-L03).** `confirm_native_preparation` returns only `Result<NativePreparationCommit>` and checks only the common originals and the readiness postimage (`state/execution/native_phase/preparation.rs:331–345`); it has no exact-preimage or absence branch. This increment therefore adds **no rollback/absence classification**: a confirmation `Err` is never interpreted as rollback.
   - `Known` → the commit is retained in the custody (already done by the body) and the job's `preparation_due` is cleared; the predicate no longer selects it.
   - `Held` (any confirmation `Err`) → `preparation_backoff` 100 ms doubling to 5 s (mirroring `closure_retry`, `runtime/phase_jobs.rs:866–874`), `preparation_due = now + backoff`.
   - `NotAttempted` (busy admission) → not an attempt: `preparation_due` and `preparation_backoff` are unchanged, and a separate `preparation_busy` counter is incremented for observation.
   - **Where the outcome is stored.** Each `PreparationSweep` item is `(Weak<Job>, Arc<NativePreparationCustody>)`. After the await, the loop upgrades the `Weak<Job>`; if it upgrades and `Arc::ptr_eq(&job.state.preparation, &custody)`, it applies the outcome under one short `job.state` lock; otherwise it skips the update (a Known commit stays retained in the custody either way). No strong Runtime or Job backlink is added.
   No outcome writes Task, Unit or operation rows, revokes anything, retries preparation, or grants dispatch.

**What this does not do.** A Known preparation commit still leaves the job Held under RN's `nonsuccess_step` until RN-1b (bound/known-commit non-success closure) exists (RN1 l.875); this HOW does not add RN-1b, does not retry preparation, does not classify rollback/absence, does not confirm helper intents (D12 deferred), and does not change G3. It only makes the designed preparation known-commit observation reachable, so that later closure can rely on it.

**Controls (P; none executed).**
- DC1 (positive): a cfg(test) fault seam makes `begin_native_preparation` return `Err` after its commit for one Unit (fault-only, Task-scoped like CA7's seam). Assertions: the sweep calls the reconciliation once per due wake; `NativePreparationCommit` becomes Known (observed through `PreparationFacts`); no Task/Unit/operation row changes; the job stays Held under RN.
- DC2 (precommit variant, R2 DC-M02): the fault fires before commit. Assertions: every confirmation returns `Held`; `known` stays None; no retry, no rollback classification, no Task/Unit/operation write.
- DC4 (backoff, R2 DC-M03): reuses DC2's genuine retained plan, which stays `Held` across turns. A cfg(test) seam issues extra service wakes (`wake.notify_one`) more often than the backoff. Assertions, from per-job attempt timestamps recorded by a cfg(test) observer: consecutive attempts are spaced by at least 100, 200, 400, … ms up to 5000 ms, and wakes inside the backoff window produce no attempt. **R3 (R2-L03):** the same cfg(test) observer (read-only, extending `observed_jobs`) also reports the stored `preparation_backoff` after each `Held`; DC4 asserts the exact sequence 100 → 200 → 400 → 800 → 1600 → 3200 → 5000 → 5000, which checks the cap without any wall-clock upper bound. DC1 stays the positive for caller wiring and Known retention.
- DC3 (shutdown): **R3 (R2-L02) fixes the order.** A nongrant cfg(test) synchronization seam (Task-scoped, like CA7's fault seam; it only parks and resumes, it grants and records nothing) parks the service loop **after** `reconcile_preparations` has returned the genuine due custody and **before** `try_enter`. The test then starts shutdown, waits until shutdown holds `control_admission` and has set `stopping`, and releases the seam. Assertions: `try_enter` returns `NotAttempted`; `preparation_due`/`preparation_backoff` are unchanged and `preparation_busy` increments; no confirmation runs; and the **service join completes** within the existing bound without its timeout firing (`runtime/service.rs:126–143`). It does not assert that the whole shutdown succeeds, since a Held job may still report pending closure (`runtime/service.rs:153–155`, `runtime/phase_jobs.rs:841–849`).
- Mutants: remove the `reconcile_preparations` call (DC1: `known` stays None); replace `try_enter` by awaiting `enter` (DC3: shutdown join waits until its timeout); drop the backoff (DC4: an attempt on every wake); treat `NotAttempted` as `Held` (DC3: backoff advanced while busy).
