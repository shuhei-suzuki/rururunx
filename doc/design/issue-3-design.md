# Issue #3 design

`git::WorktreeManager` exposes create/status/ensure_mutation_allowed/lock_review/verify_review/unlock_review/cleanup. TaskId resolves exact persisted Project/Goal ownership. Git runs directly with argv and scoped CWD, removes inherited repository-routing environment variables, retains native config/hooks, and never uses force or no-verify.

Project root must be canonical exact Git top-level. Supported worktree namespace is a normal descendant of root with no symlink ancestors. Task path is a direct child, has exact top-level and shared Git common-dir, and attached branch matches its durable binding. main/master/configured base are protected. default names are worktree/issue-N + feature/issue-N, or task UUID for Tasks without Issue.

Store validates a typed WorktreeLock {active,revision,worktree,branch,reason} and exact binding. Its immediate transaction checks both existing locks and Executor Session reservations. Starting/Running/WaitingApproval/WaitingHuman/Lost are conservative live reservations; verified terminal sessions do not reserve; Lost remains reserved until explicit recovery verifies process death. Assigned Task branch/path cannot silently change.

Creation persists binding/intent, reserves a maintenance lock, invokes git worktree add and releases after success. Failure keeps binding/lock/intents for explicit reconciliation; no deleting a hook-created tree. Cleanup similarly reserves a lock, verifies source and merged ancestry, removes the worktree then locally deletes the merged branch. Partial failure leaves the lock/intent. Records and audit retain provenance after cleanup. Status is a synchronous local operation; future scheduler callers should run it on a blocking worker, not a busy poll.

Review hardening: Task worktree/branch ownership is unique per Project inside the same immediate transaction, preventing duplicate Issue creation races from creating aliased owners. Executor sessions require exact task scope/path; actor/role/path cannot change on updates. Project roots/namespaces may not overlap or duplicate repository identities. Git identity uses canonical primary common-dir and the configured base's root commits; linked source roots and changed/replaced history are rejected. The Project registry (#26) will produce this identity.

Failed post-reservation review verification releases the ungranted lock and audits its ID; actual immutable reviews that later change remain blocked. Cleanup verifies native branch -d's upstream-or-root-HEAD ancestry before removing the worktree. Base refs are fully qualified. Only ancestry-preserving merges are currently supported by cleanup; squash/rebase cleanup needs explicit evidence in the GitHub workflow. Native GIT_CONFIG_* inputs/PATH remain intentional runtime/native configuration; adapters prohibit per-project Git routing overrides. Logical locks do not prevent external races, including ignored files written after the last safety check. Library callers can explicitly release record locks; full lock snapshots are audited, and verified review validity still requires verify_review evidence.

Native cleanup falls back to root HEAD when upstream resolution fails, including pruned tracking refs ([Git branch implementation](https://github.com/git/git/blob/master/builtin/branch.c), `branch_merged`). Worktree namespace changes are rejected after any bound Task, preserving updateability of old tasks. Dirty inspection uses Git's no-optional-locks mode. Release errors retain the lock ID and original verification error. Cleaned Tasks retain bindings permanently; repeated work on an Issue currently requires a distinct task naming policy (dependent workflow/registry), rather than silently reusing provenance. Full root-history identity validation currently incurs history traversal per operation; async integration must avoid busy polling and optimize this in the Project registry/freshness layer if measured overhead requires it. Store/recovery are trusted internal runtime callers: adopting existing worktrees or releasing Lost sessions requires explicit provenance/process-death evidence; separate databases do not coordinate repository ownership.
