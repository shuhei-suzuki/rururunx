## Exact new policy and prerequisites

Host official CLI authentication/settings/hooks stay native. No credential reading/copy/transfer, VM/container/user isolation or root is proposed. Cleanup is **best effort and separate from work outcome**; leftover resources alone must not block a Task. Subscription usage-quota exhaustion means waiting. Bounded custody/worker/retained-session resource admission is separate: Phase1 may choose cancellation-aware waiting or capacity refusal before effects, while preserving finite limits.

- **P2:** Review and verification target a commit SHA, not the mutable worktree state. Leftover writes cannot change the reviewed object. Verification must consume committed content/its own SHA snapshot, rather than merely label a live-worktree run with a SHA.
- **P3:** Every retry gets a NEW worktree; failed cleanup is recorded for later collection rather than blocking/reusing it.
- **P4:** Each Task gets a port range, temporary directory, Docker project name/labels supplied via environment. Shared Gradle/Bazel/sccache and Git automatic gc/maintenance/fsmonitor are disabled or Runtime-centralized so stopping A does not stop B. Shared refs/object DB, late callbacks/CAS and external effects that are not covered must remain explicit.

The classifications below are **proposed migration dispositions**, not permission to edit or unqualified positive capabilities. “REMOVE old gate” means its whole-workload-proof prerequisite is obsolete after the replacement P2–P4 route exists; it does not mean ignore malformed input, wrong identity or unsupported native protocol.

## Missing P2–P4 producers and concrete residuals

1. **P2 not complete:** SourceSnapshot/Evidence carry revision (`workflow.rs:206,223`) and WorktreeManager verifies SHA (`git.rs:244`), but current verification/review collectors consult live HEAD/status/CWD. No general committed-object verification snapshot producer or result-to-exact-SHA command runner exists in these APIs. A leftover process cannot alter the commit object, but can alter a live build input or external dependency; declaring SHA in metadata is insufficient.
2. **P3 not complete:** Task has one branch/worktree; create explicitly refuses it. Engine::retry does not allocate new worktree, attempt session identity or resource namespace. Need causal predecessor→new-attempt CAS and generation-fenced late callbacks without requiring old cleanup success.
3. **P4 absent:** Search found no actual per-Task port allocator, temporary-directory allocator or Docker project/label allocation contract in runtime sources. Existing arbitrary environment map is a carrier, not allocator/proof of child use. TMPDIR is native baseline/control in policy; Runtime-owned assignment needs explicit authoritative namespace without allowing arbitrary HOME/PATH/auth override. Ports in env cannot prevent a tool ignoring them; conflicts remain diagnosable. Docker labels do not authorize global prune or prove deferred jobs stopped.
4. **Shared daemon handling absent:** runtime sources do not centralize/disable Gradle/Bazel/sccache or automatic Git gc/maintenance/fsmonitor. `git.rs:555` preserves native Git config; `--no-optional-locks` status is not fsmonitor/maintenance neutralization. Native hooks remain mandatory; shared common refs/object DB can still be modified by old processes. Need explicit Runtime-authorized shared Git actions, review-SHA object retention, maintenance coordination; separate worktrees alone are no guarantee.
5. **Late callbacks/CAS:** Existing P/G/T/Session/Workflow CAS, captured attempt Control, original frame/pending digest must remain. Cleanup warning must not allow old asynchronous jobs to publish evidence/grants to a new attempt. Scope by Task alone is insufficient where old/new attempts use distinct worktrees but one mutable Task binding.
6. **External actions:** Workflow's recorded observations and irreversible phase fences prevent PR/merge/deploy/API duplication. Fresh worktree/ports do not undo remote effects. Keep true action uncertainty and idempotent reconciliation; do not turn every Lost into successful work or retry every external action.
7. **Auth/environment ambiguity:** Existing Codex/Claude functions accept frozen OS pairs and explicitly select provider env refs; no auth-file reads were performed in this inventory. The new prohibition must keep credentials inside normal native authentication. Whether pass-through of existing inherited process environment is acceptable differs from application inspection/copying native credential values; no new extraction/transfer is proposed. Native keychain/HOME/config/hooks must not be copied into new isolation HOME.
